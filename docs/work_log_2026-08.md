## 二、討論方法與它實際換到的東西

### 第一階段：技術視角（使用者工作流 / Agent 能力 / 安全治理）

硬性要求：每個提案必須附檔案:行號證據，並分別回答「使用者現在怎麼繞過」
「不做會出什麼具體錯誤」「具體事故情境」——答不出來視為假需求剔除。

### 第二階段：使用者角色直接辯論

三個角色：後端工程師（甲）、DBA（乙）、業務 PM（丙）。第二輪讓他們
**直接互相寄信**、讀對方的完整提案，不經轉述。這換到三件轉述問答做不到的事：

**1. 五個提案其實是同一個功能。** 三人各自提的「執行查詢面板」「查詢視窗」
「用中文問資料」是同一個東西，規格完全不同。他們自己併掉了，收斂成一個工作台、
兩種輸入模式、一個開關切換，**不做兩套**。EXPLAIN、DDL 驗證、結構樹也同樣各被
提了兩三次。分開問會拿到三張規格互斥的票。

**2. 長出一個三人初始提案都沒有的功能。** 甲質疑丙：你要 SQL 收起來不看，又要
一鍵生成給老闆的摘要——沒人覆核過的數字直接進決策簡報。丙的回應是整場最關鍵的
一句：**「看不懂 SQL 跟需不需要覆核是兩件事，可以並存。」** 甲被說服撤回反對。
乙同時從把關方向提出「已核可 vs AI 自動產生」標籤。兩邊講的是同一件事，
合併成**可信度標記**。這解掉了自助 vs 把關的對立，而且不是靠誰讓步，
是靠把「看不看得懂 SQL」和「有沒有人覆核過」拆成兩個獨立維度。

**3. 再延伸出「核可會過期」。** 乙指出問題今天核可了，底層口徑之後被改掉，
丙不會發現。丙的回應是「這是我原本沒想到的漏洞，照單全收」。因此常用問題要顯示
**上次確認口徑日期 + 逾期警示**——這比自動重跑更重要。

### 主持人的裁決

- **乙的硬條件要拆成兩半**：可信度標記確實與自助查詢耦合（保護「數字流向老闆」
  這條路徑），但退回機制保護的是設計審查流程，跟丙查資料是兩條不相干的路徑，
  不該綁在同一批爭取優先權。
- **ActivityLog 該不該加欄位**：兩位參與者的理由都不是決定因素。真正關鍵是
  `list_activity()` 根本沒有任何過濾能力——加一個查不到的欄位沒有意義。
  先寫 `detail_json`，**重點是先讓資料被記錄下來，形狀之後能改、丟掉的資料補不回來**。
- **三人都漏掉的事**：丙寫下「深色介面讓我覺得這是工程師的地盤」，然後提出的解法是
  給術語加說明。病徵講對了、藥開錯了——真正的解法是淺色模式。三人都沒提，
  因為甲乙不痛，而丙不知道這是可以要求的東西。

## 三、實作：五個階段，每階段須驗收

驗收要求看**實際跑起來的截圖**，不是讀程式碼。為此在容器內架了假的 LLM gateway
與真實 PostgreSQL 16（5 萬筆資料），並用 Chromium 實際點過每個畫面。

### 階段 0：唯讀護欄改用允許清單

動手前先實測既有護欄，發現**五種繞過**，其中最嚴重的一種討論階段沒人提到：

```
EXPLAIN ANALYZE DELETE FROM orders     ← ANALYZE 會真的執行被包住的語句
SELECT dblink_exec('dbname=prod', 'DELETE FROM orders')
SELECT pg_terminate_backend(1234)
CALL some_write_procedure()
COPY orders TO PROGRAM 'curl ...'
```

`EXPLAIN ANALYZE` 那條不需要任何擴充套件。這條路徑同時服務 workbench 查詢端點與
DB Agent 的 `run_query` 工具，**兩者都不經 HITL 審批**。

修法**沒有繼續追加黑名單**（那正是它壞掉的原因），改成允許清單——這也是該函式
docstring 本來就聲明的「只允許單一 SELECT/EXPLAIN」。

### 階段 1：查詢工作台

三人合併後的單一規格：中文提問（nl2sql 產生語法後直接執行、語法收在
`<details>` 進階區）、自己寫 SQL、共用結果區、可信度標記、唯讀提示、CSV 匯出。

**過程中被截圖抓到的兩個問題**（我原本沒預料到）：切換模式時兩個表單同時顯示
（`hidden` 屬性被 `.form-field` 的 `display` 蓋掉）；可信度標記在 SQL 模式下
寫「由 AI 產生」是錯的——那是使用者自己寫的語法。

### 階段 2：執行計畫面板 + DDL 驗證按鈕

執行計畫對真實 PostgreSQL 驗證：樹狀縮排、Seq Scan 標紅、成本與預估列數、
加一句白話「掃了整張表。資料量大時通常表示缺索引」。

DDL 驗證發現**既有端點服務不到這個情境**：`validate-ddl` 驗的是文件產出後的
`03_ddl.sql` 且需要資料庫連線，但確認頁的編輯器發生在文件產出之前、設計 session
也常常沒接資料庫。新增吃編輯器文字的端點，分兩段（結構解析／實跑），
並回傳 `checked` 讓前端誠實標示驗到什麼程度。

### 階段 3：結構瀏覽器 + 資料字典

搜尋同時比對表名、欄位名、註記文字——業務單位打「退貨」命中 DBA 寫的中文說明，
工程師打 `member_id` 命中欄位名，一份介面服務兩種人。有中文說明的表用說明當標題、
英文表名退成小字副標。

## 五、實作中發現、討論階段沒看到的問題

| 發現 | 嚴重性 | 狀態 |
|---|---|---|
| `EXPLAIN ANALYZE <寫入語句>` 通過唯讀護欄 | 高，且不需任何擴充套件 | 已修 |
| `setval()`／`nextval()` 通過唯讀護欄 | 高，改動後回不去且難察覺 | 已修 |
| **ER 圖在隱藏分頁被渲染** | **每個使用者、每份文件的關聯圖都是永遠壞的** | 已修 |
| **能力探測結果只有 DB Agent 在用** | **訪談（核心流程）對降級 gateway 直接 500** | 已修 |
| LLM 失敗露出裸的 `Internal Server Error` | 不懂技術的使用者會以為整個平台壞了 | 已修 |
| 中文表名被逐字轉成 `__` | 中文命名的關聯圖不可讀 | 已修 |
| 型態名稱拼錯解析階段抓不到 | 要等真的建表才發現 | 已加提醒 |

### 兩個值得展開的

**ER 圖：一開始的猜測是錯的。** 我先猜是中文名稱造成的。把語法丟進
`mermaid.parse()` 和 `render()` 都成功、SVG 12KB——所以不是語法問題。真正原因是
`loadOutputs()` 在頁面載入時就渲染，但當下作用中的是「規格書」分頁，ER 圖的
panel 是 `display:none`。mermaid 要量測文字尺寸才能算線條座標，在沒有版面尺寸的
容器裡量到 0，產生 NaN 座標後拋錯。而切分頁只換 class 不會重畫。錯誤還被一個
空的 `catch` 吞掉（註解寫「保留原始碼文字」但什麼都沒做），所以從來沒人查得到原因。

**能力探測：整套機制只有一個地方在用。** 用一個會拒絕 system role 的假 gateway
實測：`POST /llm/diagnose` 正確測出 `system_role=False` 並存進 `app_settings`，
DB Agent 也正確降級——但同一時間 NL2SQL 與訪談都是 HTTP 500。
原因是 `LLMProvider.from_settings()` 不會自己去讀探測結果，預設是「全部支援」，
而**只有 `agent_service` 記得把 profile 傳進去**。

修法是抽 `app/services/provider_factory.py` 當唯一入口，並加一條**原始碼掃描測試**：
除探針本身外，任何檔案再出現 `LLMProvider.from_settings(` 就讓測試失敗。

```
同一個拒絕 system role 的 gateway：
  修正前  訪談 500 / nl2sql 500 / agent 200
  修正後  訪談 200 / nl2sql 200 / agent 200，送出的 system role 請求為 0
```

## 六、與原規劃的落差（都已向提案者說明並取得同意）

| 落差 | 原因 |
|---|---|
| 第一批不是「純接前端」 | 既有工作台端點以 session 為範圍，但 DB Agent 頁沒有 session，因此新增 6 個以資料庫名稱為範圍的端點 |
| 匯出是帶 BOM 的 CSV 不是 `.xlsx` | 產生真 xlsx 需要額外套件，而平台須能離線內網運作。BOM 解決的正是「Excel 打開亂碼」這個原始痛點 |
| 結構瀏覽器不是側欄、無複製表名圖示 | 做成工作台的一種模式 |
| 執行計畫不是獨立分頁 | 做成工作台的一種模式，因此無法對剛跑完的查詢直接按 EXPLAIN |

## 七、免費 OpenAI 相容 API 的實測結果

實測各家連通性（受本環境的對外代理限制）：

| 服務 | 結果 |
|---|---|
| **Google Gemini**（`generativelanguage.googleapis.com/v1beta/openai/`） | ✅ 通，回「Please pass a valid API key」 |
| Groq / OpenRouter / OpenAI / Mistral / DeepSeek / Together / Cerebras | ❌ 代理 403 拒絕 |

**建議 Google AI Studio**（免費、不需信用卡）：

```
LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai
LLM_API_KEY=<金鑰>
LLM_MODEL=gemini-2.5-flash
```

尚未進行真連線測試（需要金鑰）。替代方案是寫了一個可切換能力的假 gateway
（`PROFILE=full｜no_tools｜no_json｜no_system｜flaky`），模擬各家免費服務的實際差異，
第五節那個能力探測的 bug 就是這樣抓到的。
